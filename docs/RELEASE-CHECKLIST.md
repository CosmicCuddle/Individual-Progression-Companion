- **Close WoW** before installing. Copy the existing `Interface/AddOns/IndividualProgressionAddon/` to a safe location **outside** the AddOns directory and back up the relevant `WTF` SavedVariables. Remove the old installed addon folder only after the backup is verified.
- Extract the QA artifact into `Interface/AddOns/`. Confirm the resulting path is `Interface/AddOns/IndividualProgressionAddon/IndividualProgressionAddon.toc`. If the zip creates an extra enclosing directory, move the inner `IndividualProgressionAddon` folder to the correct location.

- Use the test plan and record results. To roll back, close WoW, remove the QA folder and restore the previously backed-up addon folder. Do **not** install a second copy alongside the N-Addon-Collection module.

## Safe pre-release checklist

- [ ] **Merge the documentation PR first, after review.** Leave the feature PR separate and unmerged until approved.
- [ ] Preserve the current stable addon folder and relevant `WTF/Account/<account>/SavedVariables/IndividualProgressionAddon.lua` file (if any).
- [ ] Review all changes to Lua, TOC, `IndividualProgressionDB`, README and test files.
- [ ] Confirm GitHub Actions Lua 5.1 syntax and mocked UI tests pass on the **actual candidate commit**; capture workflow URL.
- [ ] Test in **WoW 3.3.5a** with a known Vanilla Tier 0 character: initial opening, Refresh, reopening, Tier 0/Tier 1 sidebar, Vanilla Side Content, Settings and Escape.
- [ ] Inspect Settings → **Server progression value** on the reported Tier 0 mismatch. A valid `PD~0` is expected by client mapping for Tier 0, while `PD~1` maps to Tier 1. Confirm the server's authoritative state before editing this mapping.
- [ ] Test later tiers/expansions if suitable characters exist; never reset production progression just for QA.
- [ ] Test `Show all content` OFF/ON, persistence across `/reload`, empty SavedVariables, and preservation of minimap angle.
- [ ] Verify no UI overlap at common UI scales/resolutions and no broken long guide content.
- [ ] Check compatibility when installed alongside the intended N-Addon-Collection/NCore client suite **without two copies of the same addon loading**.
- [ ] Record results, screenshots and any known limitations in `docs/DEVELOPMENT-LOG.md` and `docs/TESTING.md`.
- [ ] If accepted, decide a new version for the standalone release (e.g. **v5.3.0 is a suggestion, not an assigned version**) and update the Lua header, TOC, README, CHANGELOG and release notes consistently.
- [ ] Produce a ZIP with one top-level `IndividualProgressionAddon/` directory containing the `.toc` and referenced Lua files; test clean extraction and update in game.
- [ ] Review, merge and tag/release the standalone addon, preserving its previous release for rollback.

## Subsequent N-Addon-Collection import

Only **after** the standalone release is approved:

1. Create a separate branch in N-Addon-Collection, based on its current `main`.
2. Update `addons/IndividualProgressionAddon/` from the exact *released standalone commit* — not from an arbitrary or unmerged feature branch.
3. Update `sources.lock.json` for `IndividualProgressionAddon.commit` and `IndividualProgressionAddon.version` to match that imported release.
4. Update suite release notes/roadmap and any packaging checks as required by that repository.
5. Validate the suite's exact folder structure and test with the core `NCore` module. Confirm there is no duplicate standalone folder.
6. Open a dedicated collection import PR for review; do not publish a new suite version until its release procedure approves it.

## Reversibility

- **Standalone testing rollback:** close WoW, restore the prior known-good `Interface/AddOns/IndividualProgressionAddon/` folder; restore SavedVariables only if necessary and from the correct account backup.
- **Repository rollback:** revert the feature PR. Do not roll back other approved documentation or user data unnecessarily.
- **Suite rollback:** revert just the collection import or use the previous suite release/package. Keep the previously pinned commit recorded for provenance.
- **No database or server recompilation** is expected for the current client-only UI work.
